## 6. Postflight + accidental-destroy incident (A8)

**Block A (SCP)** ran clean. 73 files transferred, master log 61,722 bytes, observability MD + JSON SCPed, pip freeze 216 lines, SHA-256 matched on metrics.json and per_model_metrics.csv.

**Block B (verification gate)** FAILED on two artifacts:
```
FAIL  ensemble.manifest.json present
FAIL  ensemble.joblib present
FAIL  SHA-256 all match
```

The gate used `Test-Path "$localOutDir\full\ensemble.manifest.json"` (a fixed flat-structure path). But the files are at `$localOutDir\full\models\ensemble.manifest.json` (one directory deeper, inside `models/` per the original VM layout). The files **were** SCPed successfully — the gate just looked in the wrong place.

**The `vastai destroy` command was executed inadvertently while the gate output still showed FAIL.** This is a procedural violation of the standing rule SR #33 (no destroy without gate PASS). Outcome was safe because the data was actually captured, but the rule violation must be addressed structurally.

**Recovery (Block I)**:
- Recursive locator confirmed both files at `\full\models\` with full sizes (85.4 MB + 390 bytes).
- SHA-256 of both files captured to reproducibility manifest.
- Reproducibility manifest rebuilt with full metrics + per-model test/val results + session_notes recording the incident.
- Instance 37897784 confirmed destroyed (not in account listing).

**Anomaly A8** logged: "Postflight gate uses fixed Test-Path; must use recursive Get-ChildItem -Filter to be robust against nested directory structures."
