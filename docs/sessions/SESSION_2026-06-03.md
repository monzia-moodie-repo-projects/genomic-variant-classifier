## D.2 science additions — all implemented and tested

### splits.py (hash-based algorithm)

**Critical design decision:** Replaced `GroupShuffleSplit` with `hashlib.md5`-based
gene assignment. `GroupShuffleSplit` re-randomizes when the total gene count
changes — adding 50 new genes to a 50-gene dataset produces a completely
different holdout assignment. The hash-based approach gives each gene a
deterministic score in `[0,1)` keyed on `f"{seed}:{gene}"`, so:

```
holdout_genes(df_v1) ⊆ holdout_genes(df_v2)   when df_v2 ⊇ df_v1
```

This satisfies Rule 6 (longitudinal-comparison reproducibility) and the
`test_hash_stability_across_data_versions` invariant in `test_splits.py`.

**Functions added:**
- `gene_stratified_split(df, test_frac, val_frac, seed)` → `(train_idx, val_idx, test_idx)`
- `unseen_gene_holdout_split(df, holdout_frac, seed)` → `(train_idx, holdout_idx)`
- `split_summary(df, splits_dict)` → DataFrame

**Tests: 12/12 pass** in `tests/unit/test_splits.py`

### ntqr_evaluator.py

NTQR r2 accuracy bounds without a labelled test set. Clinically important for
VUS pathogenicity estimation. Runs in stub mode (all bounds `None`) when `ntqr`
is not installed. SR #31 smoke test required before adding to `requirements.txt`.

### topological_ph.py (Adopt #20)

PH features over STRING v12 gene–gene interaction graph. Leakage guard
(`train_genes_only=True` by default) restricts PH computation to the training
gene subgraph. Test genes get default (zero/one) values. Runs in stub mode when
`gudhi` is absent.

### ablation_npig_permutation.py (C3 hypothesis)

Permutation ablation for `n_pathogenic_in_gene`. Critical fix (F-10): npig is
recomputed from the **shuffled** `y_train` labels, not from the original labels.
Using original labels would test "what happens to AUROC when npig is correct but
labels are random" rather than "what happens when npig encodes no real signal".
Exit code 0 = SIGNAL (genuine variant-level signal), 1 = MEMORISATION (gene
identity dominates), 2 = error.

## Path A: --min-review-tier silent no-op (HIGH) - fixed end to end

Second workstream on 2026-06-03 (separate from the SR #31 ntqr/gudhi work above).

### The bug
`DataPrepPipeline._load_and_label` applied the review-tier filter only inside
`if "ReviewStatus" in df.columns:` with no else branch. Neither
`clinvar_grch38_clean.parquet` nor the dirty parquet ever carried a `ReviewStatus`
column, so `--min-review-tier 3` (the default) was a SILENT no-op on every run in
project history, including Run 14 (Test AUROC 0.9975). No test or preflight caught it.

### Audit chain
- `probe_review_status.py` (read-only): joined CLNREVSTAT from the ClinVar VCF
  (4,154,171 keys) onto the labeled cohort (1,686,333) by chrom:pos:ref:alt. 91.7%
  join. tier dist {1:13374, 2:334529, 3:1142111, 4:56688}. tier<=3 = 1,490,014 = the
  real tier>=3 training size (budget holds, ~Run-14 scale). -> Path A feasible.
- Decision: Path A (make tier>=3 real) over Path B (run all-labeled).

### Fix (4 parts)
- Part 1 (f24bfc6 scripts, 6142d87 incident): `augment_reviewstatus.py` attached
  `ReviewStatus` to the clean cohort from the VCF (underscores->spaces; backup-first,
  atomic, idempotent). Verified on disk: 4,399,089 rows unchanged, 0 null / 0 dup
  preserved, non-empty=3,974,573, tier<=3 KEEP=1,490,014, 17 cols.
- Parts 2-3 (b494544): fail-loud guard in `real_data_prep.py` (raises if
  `min_review_tier<5` and `ReviewStatus` absent); drops `review_tier` after filtering
  so it cannot leak as a feature. `tests/unit/test_review_tier_filter.py` (fires /
  raises / disabled). LOVD tests `min_review_tier 0 -> 5` (their lowercase
  `review_status` never matched `ReviewStatus`, so tier filtering was a no-op there too).
  Full unit suite 713 -> 716 passed, 1 skipped, 0 failed.
- Part 4 (3de282a): `preflight_run15_baseline.py` ReviewStatus present+populated
  NO-GO gate; preflight VERDICT GO with all 5 gates including the new one
