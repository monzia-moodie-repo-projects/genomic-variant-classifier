## Bug 2 — ESM-2 stall (fixed, validated, shipped THIS session)

**Fix (all sandbox-validated before apply, then committed):**
- `esm2.py`: added `_cuda_available()`, `_resolve_device(None|"auto" → cuda if available)`; module-level UniProt index cache + `_load_uniprot_index(path) → {GENE_UPPER: sequence}` (first row per gene, case-insensitive); new `__init__` params `device`, `uniprot_index_path`, `allow_network` (defaults False when an index is supplied → fail-loud, no network); `_get_sequence` reads the local index first.
- `real_data_prep.py`: added `esm2_uniprot_index_path` + `esm2_device` config fields; passed both into `ESM2Connector`.
- `run_phase2_eval.py`: added `--esm2-uniprot-index` (default None so existing callers/G1 unaffected) + abort-if-set-but-missing guard before `AnnotationConfig` build.
- `scripts/build_uniprot_index.py` (new, tracked): one-time offline bulk download of the reviewed human proteome → `data/external/uniprot/uniprot_human_reviewed.parquet`. Produced **20,190 genes**, median seq len 417 aa (parquet gitignored; SCP'd to box).

- `tests/unit/test_esm2_uniprot_index.py` (new): 4 tests (local-index no-network, missing-gene fail-loud, legacy-network fallback, device auto-detect) — all pass; existing ESM-2 tests stay green.

### Unseen-gene-holdout (UGH) ablation — the decisive generalization result

`--unseen-gene-holdout` retrained the full 13-model ensemble on a **gene-disjoint** split (seed 42, holdout_frac 0.20): train 825,538 rows / 9,978 genes, holdout 213,436 rows / **2,407 genes with zero training overlap** (actual frac 0.194).

- **ENSEMBLE_STACKER AUROC = 0.9988** on the 2,407-gene holdout.
- **C3 falsifier (b) PASS: 0.9988 vs 0.95 threshold.**

Interpretation: the ensemble holds essentially identical AUROC on genes it never trained on, so it does not depend on having seen a gene's other variants. **Open caveat (do not over-claim):** this clears "model memorized specific trained genes," but does NOT by itself clear `n_pathogenic_in_gene` (still #1 feature) as label leakage if that feature is computed corpus-wide over all ClinVar including the held-out genes. Airtight resolution requires confirming whether `n_pathogenic_in_gene` is computed train-only-per-fold vs corpus-wide, and recomputing train-only if the latter.

### CRITICAL FINDING — ESM-2 effectively dormant at full scale

ESM-2 computed delta for **3,451 missense variants** (3,435 nonzero) — the *same count as the smoke* — against a ~1.49 M cohort, i.e. ~0.3% coverage; `esm2_delta_norm` is zero for the rest, which is why it fell out of the Top-10 (it was #8 at smoke with ~99.5% coverage). This empirically confirms the known **HGVSp-parser gap**: ESM-2 coverage is gated on populated `protein_pos`/`wt_aa`/`mut_aa`, and only ~3,451 variants currently have them. **Run 15's 0.998x AUROCs therefore rest on the tabular + constraint features, not ESM-2.** The fix was still correct and necessary: the local-index/no-network change was the genuine unblocker (even 3,451 variants across many genes would have triggered hours of serialized REST + ban risk), and the GPU auto-detect is forward-looking — it pays off once the HGVSp parser raises coverage toward ~1 M. Multi-gene-symbol token (`MYH11;NDE1`, 16/3451 unscored) still pending the split-on-`;` refinement.

### Other findings (non-blocking)

- **CatBoost GPU memory pressure:** logged `less than 75% GPU memory available (Free 3.7 / 24 GB)` every fold — PyTorch's caching allocator (ESM-2/GNN/NN models, one long-lived process) reserves freed GPU memory rather than returning it to CUDA, leaving CatBoost's separate context only ~3.7 GB. CatBoost trained fine (OOF 0.9989). Future hardening: `torch.cuda.empty_cache()` between model families or `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`, or order CatBoost ahead of the torch models.
- CatBoost `best_iteration=1000` (used all iterations, no early stop) and `Default metric period is 5 because AUC … not implemented for GPU` — both benign.
- KAN subsamples 561,365 → 100,000 per fold by design (early-stopping per fold).
- gradient_boosting ~45 min per phase (sklearn GBM, sequential) and SVM ~58 min — the two CPU long poles; GPU sat at 0% during these, a future split-CPU-vs-GPU efficiency note.

## Infrastructure lessons (tracked follow-ups)

1. **Background launch over SSH must detach stdin** — `nohup … > log 2>&1 &` *without* `< /dev/null` keeps the SSH channel open; the launch "returned" only visually and the local terminal silently swallowed all subsequent input for ~1 h. Standing fix: `nohup bash … > /tmp/run15_full.log 2>&1 < /dev/null &`. The run itself was never affected (nohup, reparented to init).
2. **Read-only checks get fast-fail flags** — `ssh -n -o ConnectTimeout=20 -o BatchMode=yes` so a dead box fails in 20 s instead of hanging.
3. **`Run15_Smoke.ps1` poll-bail bug** — the PS poll loop terminates after one iteration regardless of `-SmokeTimeoutMin`, falsely reporting a timeout. Bypassed via server-side wait loops; still to fix.
4. **Stale `$f` PowerShell variable** — a `$f` left set from an earlier `str_replace`-style grep caused a double-quoted SSH body to expand it instead of passing literal `$f` to bash, producing a bogus `MISSING ×11`. Use single-quoted SSH bodies; clear with `Remove-Variable f`.
