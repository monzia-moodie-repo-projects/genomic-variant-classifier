## 1. ScalableSVM WinError 1450 crash (fixed)

### Symptom
`ScalableSVM.predict_proba` failed with `OSError: [WinError 1450] Insufficient system resources exist
to complete the requested service` when scoring the full ~304k-row Run-15 test split. The crash
surfaced during the `no_gene_level` ablation's evaluation stage (it had never been hit before because
prior ablation arms exited earlier).

### Root cause
`predict_proba` averaged the bagged RBF estimators with `Parallel(n_jobs=self.n_jobs)` where
`n_jobs` defaulted to `-1` (all cores). With 25 bags each materialising a dense kernel block against
a 304k-row X, the simultaneous worker allocation exhausted Windows desktop heap / handle resources.
The *fit* path uses the same `-1` but never crashed (bag fits are sequential in memory pressure terms
and joblib memmaps X); the failure was specific to the predict fan-out over many bags at full row count.

### Fix
Added `_resolve_n_jobs()` to `scalable_svm.py`:
- default cap of 4 workers (not all cores),
- honoured `GVC_SVM_NJOBS` environment override,
- never exceeds `min(cpu_count, n_bags)`,
- serial fallback on `OSError`.
A follow-up patch corrected a malformed-env edge case (garbage env value previously left it uncapped).
The fit path was deliberately left at `n_jobs=-1` (it never crashed and fit is the expensive stage).

### Validation
`tests/unit/test_scalable_svm_njobs.py` -- 3 passed (deterministic; `cpu_count` mocked to 8). The
`no_gene_level` arm then completed evaluation end-to-end with `GVC_SVM_NJOBS=2`.

### Algorithm note (ScalableSVM, bagged_rbf mode)
For large N an exact RBF SVM is O(N^2-N^3). The connector instead trains an ensemble of RBF SVMs on
bootstrap subsamples (each <= `svm_max_subsample` rows, up to `svm_max_bags` bags) and averages their
calibrated probabilities. Averaging is order-independent, so bag fit and bag predict parallelise
cleanly -- which is exactly why the predict fan-out, not the maths, was the failure point.

## 2. `no_gene_level` ablation -- third arm complete (gene-channel question closed)

The standing scientific concern was that `n_pathogenic_in_gene` (and the gene-level channel generally)
might inflate AUROC via gene-prevalence memorisation rather than per-variant signal. Three arms, each
trained on a 150k-row subsample, 3-fold OOF, seed 42, heavy models skipped for cost (`--skip-nn
--skip-svm --skip-mc-dropout --skip-kan --skip-shap --skip-permutation`):

| Arm | Description | Test AUROC | Delta vs full |
|-----|-------------|-----------:|--------------:|
| `full` | all features | 0.9982 | -- |
| `no_gene_prevalence` | zero `n_pathogenic_in_gene` only | 0.9980 | -0.0002 |
| `no_gene_level` | zero all 4 gene-level features (incl. `gene_has_known_disease`) | 0.9978 | -0.0004 |

Per-consequence, the effect concentrates entirely in the loss-of-function subgroup:
LoF AUROC 0.9447 (full) -> 0.9156 (no_gene_prevalence) -> 0.9096 (no_gene_level).

**Verdict:** the gene channel is not what drives the headline ~0.998. Removing all four gene-level
features costs 0.0004 AUROC overall, and even the most affected subgroup (LoF) stays > 0.90. The
gene-prevalence memorisation concern is resolved -- it is a small, interpretable contribution
localised to LoF variants, not a global inflation. Results persisted to
`outputs/ablation_run15/ablation_results.parquet`.

## 3. ESM-2 activation via AlphaMissense protein coordinates (the session's main goal)

### Why ESM-2 was a silent zero
`esm2_delta_norm` requires per-variant `protein_pos` / `wt_aa` / `mut_aa` (single-letter). No existing
connector surfaced these (`protein_change` is 100% null in the processed parquet; the column the old
ClinVar path expected does not exist in variant_summary). With those columns absent, `esm2.py` took its
documented "columns absent -> 0.0" path on every run.

### Approach
`ProteinCoordConnector` (`src/genomic_variant_classifier/data/protein_coords.py`) streams
`AlphaMissense_hg38.tsv.gz` once, keeps only rows whose `(chrom,pos,ref,alt)` appear in the cohort
(chrom normalised: AlphaMissense `chr1` vs cohort `1`), parses the `protein_variant` field (e.g. `V2L`)
into the triple via `parse_am_protein_variant` (`hgvsp_parser.py`), caches a small index parquet, and
left-joins the three columns. AlphaMissense is defined against the UniProt canonical sequence, so its
positions match the sequence ESM-2 fetches -- which is what makes the `esm2.py` wt_aa cross-check pass
at a high rate (RefSeq/HGVSp coordinates would not).

### Gate A -- join coverage (PASS)
Built the index over the full cohort:
- cohort rows: 4,420,180
- missense rows: 2,488,903 (56.3%)
- missense with protein_pos: 2,405,448 = **96.6%** of missense.

### Gate B -- ESM-2 produces real signal (PASS)
Proof-of-life on n=500 sampled missense:
- 480/500 got coordinates (96.0%, consistent with Gate A),
- **476/480 = 99.2% effective coverage** (esm2_delta_norm > 0 *after* the line-314 wt_aa-vs-UniProt
  guard). The 99.2% confirms the UniProt-canonical coordinate choice: only 4 candidates failed the
  cross-check (isoform edge cases).
- The transformers `EsmModel` LOAD REPORT (`lm_head.* UNEXPECTED`, `pooler.dense.* MISSING`) is benign:
  `esm2.py` uses per-residue encoder hidden states, not the discarded LM head or the (unused) pooler.

### Wiring
Step 10b inserted into `real_data_prep._annotate_scores` immediately before the EVE step: populate
protein coords, set `is_missense` from `consequence`, set `codon_position` from `protein_pos`. This
makes the next data-prep regen bake the columns into fresh splits (it does not itself trigger a regen).

## 4. Regression introduced by the wiring, and the fix

Wiring step 10b broke the full suite: **12 failed, 758 passed, 6 skipped**. Single root cause:
`ProteinCoordConnector` *raised* `FileNotFoundError` when `alphamissense_path` was `None` (the
`AnnotationConfig()` default used by every unit test and any box without the 613 MB TSV), crashing
`_annotate_scores`. The 12 were 10 `TestAnnotationPipeline` tests + 2 LOVD silent-zero tests -- i.e.
the wiring broke the whole annotation contract, not just the connector's own tests.

Every sibling connector (dbnsfp, spliceai, omim, clingen, dbsnp) warns-and-stubs on a missing path;
the connector had broken that pattern. Fix:
- **No data source** (no cache and no AlphaMissense file, whether `None` or a missing path): warn and
  return the frame **unchanged** (no new columns, pre-10b shape). ESM-2/EVE handle absent columns.
- **Source present but zero cohort matches:** add all-`NA` columns (consistent with the left-merge).
- **Fail-loud reserved for the genuine silent-zero risk:** a *present* file with a malformed header or
  a matched-row `protein_variant` parse rate < 0.90 (format drift) still raises (`ValueError`).

The choice to add *no* columns in the no-source path (rather than all-`NA`) was deliberate: it keeps
the frame's shape identical to pre-10b so no whole-frame assertion (e.g. a no-NaN check) can break.

Test changes: `test_missing_source_does_not_crash_annotate` (which asserted the old raise) was replaced
by `test_missing_source_degrades_gracefully` + `test_missing_source_none_path_degrades_gracefully`;
`test_parse_rate_guard` (present-but-garbage -> `ValueError`) and `test_build_join_cache` (populate path,
`NA` for the non-matching row) were kept. All four behavioural paths were validated in a sandbox against
the real connector + parser before delivery.

## 5. Hygiene: `datetime.utcnow()` deprecation

`variant_ensemble.py:1344` used `datetime.utcnow()` (deprecated in 3.12; returns a naive datetime).
Replaced with `datetime.now(timezone.utc)` (+ `from datetime import timezone`), so the persisted
`saved_at_utc` serialises with an explicit `+00:00` offset. Guarded, idempotent, ast-verified patcher.

## 6. Open items / observations (not regressions)

- **ESM-2 regen strategy -- the one open decision.** `esm2.py` is **not batched**: `annotate_dataframe`
  loops `for row in candidates.itertuples()` and calls `_compute_delta` per variant (two forward passes
  each); `seq_cache` only amortises the UniProt sequence lookup per gene. Measured 1213.9 ms/variant CPU
  first-pass (naive 839 h to 2.49M; warm-cache + GPU lower, but unbatched it is still bounded by
  per-variant forward passes -- on the order of many GPU hours, not minutes). Earlier "$5-10/minutes"
  framing was too optimistic and is corrected. Given the ablation-demonstrated feature redundancy,
  recommendation is to (a) batch `_compute_delta`'s forward passes, and/or (b) measure ESM-2's
  *contribution* on a ~150k subset before paying for the full 2.49M regen. Decision pending.
- **`torch_scatter`/`torch_sparse` `0xc0000139` on Windows** during `test_ablate_gnn.py` collection --
  `importorskip` catches it, test skips cleanly. Pre-existing; GNN is GPU-only locally. Not a regression.
- **`.fillna` downcasting FutureWarnings** at `variant_ensemble.py` lines 368,389,393,432,437,445,450,
  455,462,467 (engineer_features). Accumulating; future hygiene (call `.infer_objects(copy=False)` or set
  `future.no_silent_downcasting`).
- **EVE** now has its protein columns available but still needs its own EVE score files; stays a 0.5 stub
