## 1. The smoke saga (root cause + fix)

The cloud "all-models" smoke was paying the **full annotation cost** before subsampling.
Root cause: `smoke_all_models.py` / `Run15_Smoke.ps1` invoke `run_phase2_eval.py
--max-train 3000`, but `--max-train` subsamples at `run_phase2_eval.py:262` — *after*
`DataPrepPipeline` (line ~212) has already annotated all ~1.68 M ClinVar rows. There is
no cross-run split cache (`real_data_prep._save_splits` writes splits but nothing loads
them). The dominant cold cost is the source-index builds (SpliceAI ~1.5 min,
AlphaMissense ~3.5 min on that host), not variant count.

Fix: `make_clinvar_smoke.py` built a stratified 80 k subset
(`data/processed/clinvar_smoke.parquet`); `Install_Run15Smoke_FastClinvar.ps1`
(count-guarded, idempotent, backup) pointed the smoke `--clinvar` at it while leaving the
full ClinVar uploaded for the full run. Smoke then ran ~13 min GREEN: SMOKE_EXIT=0, all
13 models fit, KAN ran, GNN non-degenerate. `cnn_1d` 0.52 at 3 k was flagged as a
suspected scale artifact (confirmed below).

## 4. Per-model algorithm comparison (mechanism / performance / interpretation)

- **Gradient-boosted trees (xgboost 0.9991, lightgbm 0.9990, catboost 0.9989,
  gradient_boosting 0.9983):** sequential additive trees fitting residual gradients.
  Dominant family here — they exploit the tabular feature interactions (CADD, LOEUF,
  SIFT, gnomAD constraint, `n_pathogenic_in_gene`) most efficiently. xgboost/lightgbm
  carried isotonic calibration before OOF scoring.
- **Bagged trees (random_forest 0.9985):** parallel decorrelated trees; near-boosting
  performance, lower variance, no calibration step.
- **Neural tabular (tabular_nn 0.9985, mc_dropout 0.9985, deep_ensemble 0.9986/0.9987):**
  MLPs over standardized features; deep_ensemble (multiple seeds averaged) edges the
  single nets and is the strongest non-tree learner — evidence the signal is partly
  smooth/continuous, not only tree-splittable.
- **Kernel methods (svm Nyström 0.9979, svm_bagged_rbf 0.9973):** RBF kernel via Nyström
  approximation / bagging to scale to ~1 M rows; slightly behind trees, consistent with
  kernel methods on high-dimensional tabular data.
- **Linear (logistic_regression 0.9969):** strong baseline; the ~0.002 gap to trees is
  the measured value of nonlinearity/interactions on this data.
- **KAN (0.9968):** Kolmogorov-Arnold network (learnable spline activations on edges);
  competitive with the linear/kernel tier — the headline result for the
  newer-architecture comparison goal, and it ran clean (prior crash fixed).
- **cnn_1d (0.8536 main / 0.8448 UGH):** 1-D conv over the ordered feature vector; the
  weakest learner, but **0.52 at 3 k -> 0.85 at 1.49 M is a pure data-scale effect**, not
  a wiring bug — it validates proceeding past the smoke degeneracy.
- **GNN (val AUC 0.6509):** GAT over the STRING PPI graph. Weak as a standalone
  classifier; its value is the non-degenerate `gnn_score` feed into the stack. Recovered
  from Run 14's all-zero regression; non-degeneracy gate now guards it permanently.
- **ENSEMBLE_STACKER (0.9984 / 0.9988):** meta-learner over base-model OOF predictions.
  Does not beat the top single tree on raw AUROC (the ceiling is near-saturated) but
  improves calibration/robustness and holds at 0.9988 on unseen genes.

## 6. Runbook detection bugs (none touched the run; cosmetic/detection only)

Common root: SSH's `Welcome to vast.ai` banner arrives on **stderr**; under a script
`$ErrorActionPreference='Stop'`, merging it with `2>&1` turns it into a
NativeCommandError that halts, or it pollutes a success/exit parse.

1. **`Run15_Postflight.ps1` `Invoke-Ssh`** halted at step 1/7 (`& ssh @sshBase $cmd 2>&1`
   under Stop). **FIXED** this session via count-guarded patcher
   (`Install_Postflight_SshBanner_Fix.ps1`): wraps the call in function-scope
   `ErrorActionPreference='Continue'` + `Out-String` so stderr never throws. Adding
   `-o LogLevel=ERROR` to `$sshBase` (source-level banner suppression) is a follow-up
   pending the `$sshBase` definition.
2. **`Run15_FullRun.ps1`** — **RESOLVED (no live bug).** The launch step uses `Rbash`,
   which streams remote stdout via `| Out-Host` and returns only `$LASTEXITCODE`, so the
   `launched pid …` echo never folds into `$rc`; the poll/marker survives the zero-count
   case by array semantics. The historically-reported misread predated the `Out-Host` fix.
3. **`Run15_Smoke.ps1` poll** — **FIXED** via `Install_Smoke_PollCheck_Fix.ps1`: the
   completion check now parses the first integer of the grep result and requires >= 1,
   instead of string-comparing a possibly-multiline `grep -c … || echo 0` result to `"0"`
   (the `|| echo 0` doubles to `"0\n0"` on a zero count, which `!= "0"` fires falsely).
