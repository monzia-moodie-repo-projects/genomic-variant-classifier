NOTE ON n_pathogenic_in_gene AFTER THE 2026-06-13 FIX
====================================================================================================
  The fix computes the count from TRAIN labels only. The main split is
  gene-disjoint (GroupShuffleSplit), so a TEST gene has no train variants and
  its count is IDENTICALLY ZERO. tests/unit/test_d1_d2.py::TestRecomputeNpig
  ::test_test_npig_always_zero asserts exactly that.

  So the fix did not remove the feature -- it replaced a label leak with a
  TRAIN/TEST DISTRIBUTION SHIFT: the model learns on n_pathogenic_in_gene in
  [0, N] and predicts with it pinned at 0. If the model learned
  'high count => pathogenic', every unseen gene is pushed toward benign.
  Verify directly:  X_test['n_pathogenic_in_gene'].nunique()
    nunique > 1 on a PRE-fix run (e.g. run14)  -> the leak was live
    nunique == 1 on a POST-fix run             -> dead feature + shift
