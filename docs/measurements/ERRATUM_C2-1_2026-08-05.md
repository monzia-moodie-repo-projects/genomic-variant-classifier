# ERRATUM C2-1 — the Oracle C2 surface split is cohort-dependent, not structural

**Author: Monzia Moodie**
**Written 2026-08-05, against `HEAD = origin/main = ff0eead`.**

**Applies to:** `docs/measurements/OP1_C2_DIFFERENCE_2026-08-05.txt` and
`docs/measurements/OP1_C2_DIFFERENCE_R2_2026-08-05.txt`, both committed in
`ff0eead`.

**Neither report is edited.** They record what was measured, and what was
measured is correct. This erratum records that one of their *headings* claims
more than the measurement supports.

---

## 1. What the reports say

Both partition the registry-added metadata into three surfaces:

```
ON EVERY PATH          metric_name, population_scope, population_fingerprint,
                       n_observations, n_classes_observed
ON THE OK PATH ONLY    certification_eligible, certification_blocked_by
ON REFUSAL PATHS ONLY  n_predicted_positive, n_reference_positive,
                       reference_class_support, threshold
```

The third heading reads as a **structural** claim: that those four keys appear on
refusals and not otherwise.

---

## 2. What the code shows

`registry.py:662-668`, in the applicability predicate for the probability-input
metrics:

```python
if not ctx.has_both_classes:
    return Applicability(
        applicable=True, status=None, reason=None,
        metadata={MetricMetadataKey.REFERENCE_CLASS_SUPPORT: "single_class"})
```

**`applicable=True`.** A descriptor may carry `REFERENCE_CLASS_SUPPORT` on an
*applicable* verdict, and `registry.compute`'s OK branch merges
`verdict.metadata` — so that key can reach an **OK** result.

The measurement never saw it there because none of its four cohorts produced a
metric that is **applicable on a single-class cohort**. `sensitivity` refuses on
`no_positive_reference_class`; a proper score such as `brier_score` would be
applicable on the same rows and carry the key.

---

## 3. The correct statement

| surface | status |
|---|---|
| every path — 5 keys | **structural**; all five `MetricResult` construction sites carry `**ctx.support()`, verified by reading all five |
| OK path only — 2 keys | **structural**; `certification_eligible` and `certification_blocked_by` are set only on the OK branch |
| refusal paths only — 4 keys | **COHORT-DEPENDENT**; these come from `verdict.metadata`, which `registry.compute` merges on **both** the refusal and OK branches |

So the third group is more precisely: **descriptor-supplied keys observed on
refusals in the four cohorts measured.** Which keys appear, and on which paths,
depends on the descriptor and the cohort.

---

## 4. Why this strengthens the step 3c boundary rather than weakening it

The finding step 3b drew was:

```
the finaliser owns    identity, support, certification
the descriptor owns   verdict.metadata
```

**That is unchanged, and more firmly established.** `verdict.metadata` is
descriptor-owned on **both** paths — not merely on refusals — so a finaliser
that touched it would be overreaching on the OK path too, not only when a metric
refuses.

The comment at `registry.py:665-667` is the third independent confirmation:

> `N_CLASSES_OBSERVED` is deliberately NOT supplied here: `ctx.support()` already
> provides it, and a verdict that restates a registry-owned key would collide
> with the protected set below.

A descriptor author withholding a registry-owned key **because REG-1's guard
would raise.** The invariant working before the fact rather than after.

---

## 5. Why an erratum rather than a correction

The reports are evidence of a measurement, and the measurement was sound: 24
comparisons, four cohorts, six metrics, R2 exiting 0 against a stated prediction.
Editing them to add a caveat would make them **claim to have measured something
they did not** — a cohort where an applicable verdict carries
`reference_class_support`.

The same reasoning kept R1 with its incomplete prediction intact, and REG-1's
baseline mutation report with its wrong rationales. **An artifact records what
happened; a correction belongs beside it, not inside it.**

---

## 6. What would close C2-1

A fifth cohort in which a metric is **applicable on a single-class cohort** —
`brier_score` on `no_positive_reference_class` — measured and added to the
difference set. That would show `reference_class_support` on an OK path directly,
rather than inferred from reading the predicate.

Deferred rather than done now: step 3c's design does not depend on it, and
widening the measurement to settle a heading would be scope creep into a commit
that has already shipped.

**Recorded as C2-1** in the follow-up register.
