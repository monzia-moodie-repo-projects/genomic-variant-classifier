SECTION 4 -- WHAT THIS MEANS FOR C2
==============================================================================

  THE COUNT PATH SUPPLIES NO METADATA, and that is STRUCTURAL rather
  than an omission. `metrics_from_counts(counts, parameters)` takes
  NO CONTEXT and NO POPULATION -- it cannot supply the population keys
  because it has never been given a population.

  So C2 CANNOT PASS BY ENRICHING THE COUNT PATH. Copying registry
  metadata into `metrics_from_counts` would require handing it a
  context, at which point it is doing the registry's job with a SECOND
  IMPLEMENTATION OF THE FINALISATION CONTRACT -- which the adopted
  ruling forbids, and which is the SWEEP-1 shape at the level of a
  contract rather than an algorithm.

  THE ARCHITECTURE THE MEASUREMENT POINTS TO is a finaliser both paths
  call: one authority that takes a bare result plus a context and
  attaches identity, support and certification. THIS SCRIPT DOES NOT
  BUILD IT. The extraction is specified against this evidence.

  AND ONE HYPOTHESIS WAS FALSIFIED BEFORE MEASURING. Five construction
  sites exist and REG-1 audited two, so a refusal built BEFORE
  `ctx.support()` attaches would leave artifacts with no population
  identity -- exactly what POP-1b exists to prevent. Reading all five
  showed every one carries `**ctx.support()`. THE CODE IS ALREADY
  CORRECT, and knowing that by measurement is different from assuming
  it.
